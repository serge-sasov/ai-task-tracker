## Как читать документ

1. **Coverage summary** — таблица «требование → use case»: полное покрытие всех 30 требований (R-001..R-030); требования, покрываемые не отдельным UC, а проверкой окружения/замером, помечены как `indirect`.
2. **UC-E2E-NNN** — формальный end-to-end сценарий по шаблону `harness/templates/e2e-use-case.md`: источник требований, актор, приоритет (P0 — ядро, P1 — важное, P2 — nice-to-have), preconditions, trigger, main flow (нумерованные шаги «действие -> ожидаемое»), alternate flows, error flows, ссылка на тест-данные в YAML, expected result, postconditions, cleanup, traceability.
3. **Test data reference** — ссылка на секцию `use_cases[]` в `e2e-test-data-ai-task-tracker.yaml`; YAML — единственный источник машин-читаемых данных (seed-файлы opencode, запросы, ожидаемые значения). Секреты не используются — только плейсхолдеры окружения.
4. **Правила построения сценариев** (из решений CP-1 по Q-001..Q-008): 1 задача = 1 сессия opencode (Q-002); продолжительность = конец − начало (Q-002); данные читаются из локальных файлов сессий opencode + polling ≤ 5 мин (Q-001); токены — из usage-полей сессий (Q-003); single-user без аутентификации на localhost (Q-004); хранение без лимита + ручное удаление (Q-005); UI — русский (Q-006); AI-поиск — локальная LLM через Ollama (Q-007); решения извлекаются LLM-ом из контекста сессии (Q-008).
5. **Детерминированность**: все ожидаемые значения (список задач, статусы, продолжительности, суммы токенов) вычислены заранее в YAML-фикстурах и не зависят от «живых» сессий.
