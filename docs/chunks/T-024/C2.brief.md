# C2 brief: Frontend — S-01 model column (primary +N, tooltip/aria, empty state)

## Goal
Render a «Модель» column right after «Название» on the dashboard table using
`task.models` (new optional field on the task-list DTO type).

## Inputs (path + line range)
- Type: `src/web/src/api/types.ts` (TaskListItem interface, ~lines 13–21).
- View: `src/web/src/views/DashboardView.vue` (~lines 52–77 table + header).
- UI spec contract (T-021 / cards §4.2, architecture CLS-003): column placed
  immediately after «Название».

## Rules
- types.ts: add `models?: string[]` to `TaskListItem`.
- DashboardView.vue:
  - Add `<th scope="col">Модель</th>` immediately after the «Название» header.
  - Add a `<td>` after the name cell. Use `task.models ?? []`.
  - Non-empty: show `task.models[0]` as the primary model plus a visible
    `+N` badge when `N = models.length - 1 > 0`.
  - Put the full ordered list in the cell `title` and `aria-label` as
    «Модели: m1, m2, ...» (join with ", ").
  - Empty (`length === 0`): show «Нет данных» with an accessible label
    «Модель: Нет данных» in `title` and `aria-label`.
- Do NOT modify format.ts (card artifacts only list types.ts and DashboardView.vue).
- No network calls, no new dependencies. Keep the table usable.
- Match the existing Vue SFC style (scoped <style>, class names, ru copy).

## Acceptance
- types.ts has `models?: string[]`.
- Column after Название; primary model + `+N` overflow; title/aria full list;
  «Нет данных» when empty.
- `npm run build` in `src/web` passes.

## Stop rule
Stop at the chunk boundary. If a write exceeds the budget, split — do not repeat.

## Return
Produced paths plus `npm run build` result; at most 10 lines.
