## Goal

Produce the deterministic E2E runner engine: a PowerShell entry point (`scripts/e2e.ps1`)
that manages the isolated local stack and invokes pytest, plus the pytest plugin
`tests/e2e/conftest.py` that loads the YAML dataset, generates per-UC test items,
executes them through a pluggable step-handler registry, and writes machine-readable
JSON results.

## Inputs

- `docs/chunks/T-009.json` (own set, C1 section, lines 15-55)
- `docs/tasks/T-009-e2e-automation.md` (acceptance, lines 24-36)
- `docs/analysis/e2e-test-data-ai-task-tracker.yaml` — schema lines 1-33, `use_cases` lines 274-645 (field shapes for `id/title/source_requirements/actor/priority/preconditions/steps/data/expected/cleanup/traceability`)
- `docker-compose.yml` (services backend:8080, postgres:5432, redis:6379, frontend:8081; health paths `/api/health`)
- `harness/scripts/validate-e2e-data.py` (baseline validator; C2 owns it, do not touch)

## Acceptance

- [ ] `scripts\e2e.ps1 list` loads the YAML and prints UC-E2E-001..008 with titles; no stack required.
- [ ] `python -m pytest tests/e2e --collect-only -q` collects items without error (generates from YAML).
- [ ] conftest starts the isolated stack (`docker compose up -d`, clean slate via `down -v`), polls backend health, yields base URLs, and runs per-UC steps through a step-handler registry.
- [ ] On `pytest_sessionfinish` it writes one JSON result per UC (id, name, status, steps, duration_ms, errors, timestamp) into `tests/e2e/results/`.
- [ ] The step-handler extension point is a registry keyed by step `action` prefix.

## Stop rule

Stop when all three `owns` files are written, budget/`max_write_kb` not exceeded,
no `TODO`/`FIXME` in artifacts, and acceptance bullets met. Record state with
`chunk.ps1 complete`. If the docker build smoke exceeds ~15 min, abort smoke,
`down`, note it deferred to C7.

## Return

At most ten lines: produced paths, state, and any issue id. No artifact text.
